# koishi-plugin-video-parser-all v1.7.8

## 更新日志

### 修复

- 修复抖音实况照片（Live Photo）无法发送的问题：部分接口（如 BugPk-API 短视频解析聚合 `/api/svparse`、`/api/dyjx`）对实况照片返回的作品类型是 `live` 而非 `live_photo`，导致插件既不按实况照片处理、也不按图集处理，最终一张图片都发不出去。现在把 `live`、`live_photo`、`livephoto`、`live-photo`、`live photo`、`livephotos` 统一归一化为普通图片类型，并把每条实况照片的图片并入图集，按普通图片全部发送。
- 实况照片统一按普通图片处理：实况视频一律不发送（沿用既有设计），图集有图片时按图集发送，不发视频、不发「视频链接」。
- 修复抖音实况照片场景封面被重复发送的问题：存在 `live_photo` 数据时不再额外发送封面，避免与实况图片重复。
- 修复实况照片条目只识别 `image` 字段的问题：现在兼容字符串元素与 `img`、`image_url`、`pic`、`pic_url`、`photo`、`cover` 等图片字段，以及 `video`、`video_url`、`videoUrl`、`play_url`、`play_addr` 等视频字段；图片会去重后并入图集，条目图片与视频为同一地址时不重复计入。
- 修复解析失败时错误信息被错误覆盖的问题：抖音的 `zjyh`（`video_id` 原画）兜底接口在缺少 `video_id` 被跳过时，会把前面接口返回的真实业务错误覆盖成「未取得抖音 video_id」；`dydj` 返回 HTML 页面或「空内容」时也会冲掉真实错误。现在服务端返回的带 `code`+`msg` 业务错误（如「作品未审核通过，平台暂不提供播放」）具有最高优先级，兜底跳过、空内容、HTML 响应等均不再覆盖它，最终向用户展示真实原因。
- 增强解析错误处理的健壮性：HTTP 4xx/5xx 响应体中的结构化错误信息（如网关返回的 `{code:-1,error:"服务暂时不可用"}`）现在能正确提取；HTML 跳转页、超长文本会被净化为「解析接口返回了非预期内容」，不再把整段 HTML 抛给用户；响应为字符串型 JSON 时也能正确读取 `code`/`msg`。错误优先级为「HTTP 200 明确业务结论 > 传输层错误体 > 其它错误」，临时的网关抖动不会盖过针对作品的具体原因。
- 修复 QQ 卡片 `json` 元素数据为对象时链接被静默丢弃的问题：卡片数据既支持 JSON 字符串也支持已解析对象，并为递归提取加入防循环引用保护。
- 修复图文作品「作者头像」提示与主文字消息不隔行的问题：上一轮重构把「作者头像：」提示从主文字末尾改成了独立的纯文本消息，QQ 客户端把连续两条纯文本拼接显示成「图片数量：7作者头像：」。现在默认把提示带换行追加到主文字消息末尾；同时统一处理所有连续纯文本消息（如视频无头像时的「封面：」、头像/封面/视频/音乐只发链接时的文本），给相邻项补前导换行，从发送计划层根除粘连，且各开关组合均保留原有行为作为回退。

### 平台清单调整

按 `api-new.ifphp.com` 免费接口的逐项实测结果，对内置平台识别清单做了增删（仅保留视频平台接口，音乐/工具/娱乐类接口不在范围内）：

- 新增：今日头条（`toutiao`）、千问（`qianwen`）——真实链接经短视频解析聚合可成功解析。
- 移除：小红书（`xiaohongshu`）、微博（`weibo`）、绿洲（`oasis`）、西瓜视频（`xigua`）、YouTube（`youtube`）、知乎（`zhihu`）、虎牙（`huya`）、美拍（`meipai`）、Twitter/X（`twitter`）、Instagram（`instagram`）、全民（`quanmin`）、皮皮搞笑（`pipigx`）、皮皮虾（`pipixia`）、最右（`zuiyou`）——新站无对应专属接口，且短视频解析聚合对这些平台返回「解析参数与该平台不匹配」，无法解析。
- 平台开关（`platformEnabled`）、优先专属 API（`platformDedicatedFirst`）、自定义 API 可选平台、专属 API 映射与链接识别规则同步调整；移除实测始终报「参数不全」的皮皮搞笑专属接口 `/api/pipigx`。
- 保留但需注意：TikTok（`tiktok`）、AcFun（`acfun`）、微视（`weishi`）、Dola（`dola`）后端有解析分支，但当前免费接口取不到媒体资源，属「平台支持、作品解析失败」，链接识别仍保留。梨视频在新站返回的平台标识为 `lishipin`，插件内部仍沿用 `lishi`。
